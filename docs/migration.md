# Migrating from @hyperdx/node-opentelemetry

`@clickhouse/clickstack-node` replaces `@hyperdx/node-opentelemetry`. It is a new package, built on the current upstream OpenTelemetry SDK, and it has no compatibility layer: there is no `initSDK`, no `HYPERDX_*` or `HDX_*` variable, no deprecated stub, no `opentelemetry-instrument` command and no `build/src/*` path. This page maps everything the old package offered to its replacement and lists the behavior changes that affect saved searches, dashboards and alerts.

Plain OpenTelemetry also works with ClickStack. If you would rather not use either package, see [Using the upstream SDK directly](../README.md#using-the-upstream-sdk-directly).

## Swap the package

```sh
npm uninstall @hyperdx/node-opentelemetry
npm install @clickhouse/clickstack-node
```

Uninstall the old package first: running both starts two SDKs.

| Old entry point                                                   | Replacement                                                                                                           |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `node -r @hyperdx/node-opentelemetry/build/src/tracing app.js`    | `node --import @clickhouse/clickstack-node/register app.js`, or `node -r @clickhouse/clickstack-node/register app.js` |
| `npx opentelemetry-instrument app.js`                             | `node --import @clickhouse/clickstack-node/register app.js`                                                           |
| `NODE_OPTIONS="-r @hyperdx/node-opentelemetry/build/src/tracing"` | `NODE_OPTIONS="--import @clickhouse/clickstack-node/register"`                                                        |
| `init(config)` or `initSDK(config)` in code                       | `init(options)`, with the renamed options below                                                                       |

The new entry point instruments ES module apps too, which the old package never did. `-r` (`--require`) suits tools that preload CommonJS modules, and CommonJS TypeScript on Node.js 22 and on 24 before 24.12.

Remove every `npx opentelemetry-instrument` call from package scripts and container images. Once the old package is uninstalled, `npx` would download whatever package owns that name on the npm registry.

## Environment variables

Booleans changed. The old package accepted `1`, `yes` and `true`, and its documentation used `=1`. The new package follows the OpenTelemetry rule: only `true` (any case) is true, and any other value, including `1`, counts as false.

Precedence changed too. In the old package a code option beat the environment variable (`init()` even ignored `HDX_NODE_CONSOLE_CAPTURE=0`). Now an environment variable always wins over the matching `init()` option.

| Old variable                                                                                                                                                                                               | Replacement                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HYPERDX_API_KEY`                                                                                                                                                                                          | `OTEL_EXPORTER_OTLP_HEADERS=authorization=<key>`, or `init({ apiKey })`. The old package appended `Authorization=<key>` to an existing `OTEL_EXPORTER_OTLP_HEADERS`; the new one never merges. If you send other headers, write them together: `OTEL_EXPORTER_OTLP_HEADERS=x-tenant=a,authorization=<key>`. `apiKey` is ignored, with one warning, when `OTEL_EXPORTER_OTLP_HEADERS` already holds another value. |
| `HDX_NODE_BETA_MODE`                                                                                                                                                                                       | Removed. For attributes on every span and log record of a trace, use upstream's `BaggageSpanProcessor` and `BaggageLogRecordProcessor` with plain `NodeSDK` (see [Trace attributes](#trace-attributes))                                                                                                                                                                                                           |
| `HDX_NODE_CONSOLE_CAPTURE`                                                                                                                                                                                 | Console capture is on by default. To turn it off: `OTEL_NODE_DISABLED_INSTRUMENTATIONS=console`, or an `OTEL_NODE_ENABLED_INSTRUMENTATIONS` list without `console`                                                                                                                                                                                                                                                |
| `HDX_NODE_ADVANCED_NETWORK_CAPTURE`                                                                                                                                                                        | Bodies: `CLICKSTACK_CAPTURE_HTTP_BODY=true`, with a fixed 8192-byte cap, textual bodies only and a fixed list of redaction keys. Headers: list the names in `OTEL_INSTRUMENTATION_HTTP_CAPTURE_HEADERS_*`; there is no capture-all mode, and names on the sanitize list are not captured                                                                                                                          |
| `HDX_NODE_STOP_ON_TERMINATION_SIGNALS`                                                                                                                                                                     | Removed. When the app has its own SIGTERM or SIGINT listener, the package only flushes and the app decides when to exit. An app that exits or re-raises the signal itself, as NestJS `enableShutdownHooks()` does, should await `shutdown()` first (see [Signals](#signals))                                                                                                                                      |
| `HDX_NODE_EXPERIMENTAL_EXCEPTION_CAPTURE`                                                                                                                                                                  | Removed. Crash capture is always on (see [Crashes](#crashes))                                                                                                                                                                                                                                                                                                                                                     |
| `HDX_NODE_SENTRY_INTEGRATION_ENABLED`                                                                                                                                                                      | Removed (see [Sentry](#sentry))                                                                                                                                                                                                                                                                                                                                                                                   |
| `HDX_NODE_ENABLE_INTERNAL_PROFILING`                                                                                                                                                                       | Removed; the old package never read it. `OTEL_LOG_LEVEL=debug` shows each instrumentation load                                                                                                                                                                                                                                                                                                                    |
| `HDX_STARTUP_LOGS`                                                                                                                                                                                         | Removed. | `OTEL_EXPORTER_OTLP_ENDPOINT`                                                                                                                                                                              | Same variable, but there is no default ClickStack endpoint any more: the old default `https://in-otel.hyperdx.io` became the upstream default `http://localhost:4318`. It is a base URL; the SDK appends `/v1/<signal>`, and a trailing slash is fine                                                                                                                                                             |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, `_LOGS_ENDPOINT`, `_METRICS_ENDPOINT`                                                                                                                                | Same (full URLs)                                                                                                                                                                                                                                                                                                                                                                                                  |
| `OTEL_EXPORTER_OTLP_PROTOCOL`                                                                                                                                                                              | The old package honored only `grpc` and always sent logs as JSON. Now every upstream value works, including the per-signal `_PROTOCOL` variables; the default is `http/protobuf` for all three signals                                                                                                                                                                                                            |
| `OTEL_EXPORTER_OTLP_HEADERS`                                                                                                                                                                               | Same. The package writes it from `apiKey` only when it is unset                                                                                                                                                                                                                                                                                                                                                   |
| `OTEL_EXPORTER_OTLP_TRACES_TIMEOUT`                                                                                                                                                                        | The old default was 60000 ms; the upstream default is 10000 ms. Set it, or `OTEL_EXPORTER_OTLP_TIMEOUT`, to change it                                                                                                                                                                                                                                                                                             |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG`                                                                                                                                                           | Same default (`parentbased_always_on`), but no longer written back to the environment                                                                                                                                                                                                                                                                                                                             |
| `OTEL_SERVICE_NAME`                                                                                                                                                                                        | Same variable, and it now wins over the `serviceName` option. When unset, the name is `unknown_service:` followed by the executable, such as `unknown_service:node` (the old package used `unknown_service`)                                                                                                                                                                                                      |
| `OTEL_TRACES_EXPORTER`, `OTEL_LOGS_EXPORTER`, `OTEL_METRICS_EXPORTER`                                                                                                                                      | The old package honored only `none`. Now every upstream value works: `otlp`, `console`, `none`, and `prometheus` for metrics                                                                                                                                                                                                                                                                                      |
| `OTEL_METRIC_EXPORT_INTERVAL`, `OTEL_METRIC_EXPORT_TIMEOUT`                                                                                                                                                | Same defaults (60000 and 30000 ms)                                                                                                                                                                                                                                                                                                                                                                                |

## Behavior changes

### Startup

- **No default endpoint.** Without `OTEL_EXPORTER_OTLP_ENDPOINT` the SDK sends to `http://localhost:4318`. Setting `apiKey` without an endpoint logs a warning that names the variable.
- **No key needed to start.** The old package skipped initialization when it had no key; the new one starts and logs the 401 responses. For local development and CI without a collector, set `OTEL_SDK_DISABLED=true`, which installs nothing. Otherwise a short script with an unreachable endpoint takes up to about 5 seconds longer to exit, where the old package exited at once and dropped the data.
- **No startup output.** The spinner, the configuration dump, the dashboard link and the three health-check requests are gone. Export failures appear as warnings at the default `OTEL_LOG_LEVEL=warn`.
- **Upstream exporter defaults** apply: timeouts, batch sizes and delays come from the upstream SDK.

### Signals

- SIGTERM and SIGINT now end the process with exit status 143 and 130, as Node.js does by default, after a flush. The old package exited with 0. Check PM2, systemd units and Kubernetes Jobs that test for 0.
- When the app has its own signal listener, the old package still called `process.exit()` as soon as its own shutdown finished, which cut the app's graceful shutdown short. The new package only flushes and leaves the exit to the app. An app that exits or re-raises the signal itself should await `shutdown()` first, or the last batch can be lost. With NestJS `enableShutdownHooks()`, do it in an `onApplicationShutdown` hook. The old README pattern still works without any option:

  ```js
  process.on("SIGTERM", async () => {
    await shutdown();
    process.exit();
  });
  ```

### Crashes

- **Crash capture is on for every entry point.** The old `init()` never installed its exception handlers, and neither did the preload unless `HDX_NODE_EXPERIMENTAL_EXCEPTION_CAPTURE=1` was set. Now every uncaught exception produces a record, is printed to stderr as Node prints it, and exits with code 1 after a bounded flush.
- **The crash record changed shape.** It used to be a span named `<Type>: <message>` from the `@hyperdx/instrumentation-exception` scope, with `exception.parsed_stacktrace`, `exception.tags`, `exception.modules` and `app.*`, `device.*`, `os.*` and `host.cpu.*` attributes. It is now a FATAL log record from the `@opentelemetry/instrumentation-runtime-node` scope: body `exception`, severity number 21 and no severity text (ClickStack stores an empty `SeverityText`), with `exception.type`, `exception.message` and `exception.stacktrace`. Update saved searches and alerts, for example to `SeverityNumber = 21`.
- **Unhandled rejections.** Only apps that set `HDX_NODE_EXPERIMENTAL_EXCEPTION_CAPTURE=1` or called `initSDK({ experimentalExceptionCapture: true })` had rejections recorded while the process kept running. Every other app already crashed on an unhandled rejection, as Node.js does by default. The new package follows Node.js: the process crashes, with a FATAL record. To restore record-and-continue, add your own listener:

  ```js
  const { logs, SeverityNumber } = require("@opentelemetry/api-logs");

  process.on("unhandledRejection", (reason) => {
    logs.getLogger("app").emit({
      severityNumber: SeverityNumber.ERROR,
      severityText: "ERROR",
      body: "unhandledRejection",
      exception: reason,
    });
  });
  ```

  This listener turns off Node's crash for every rejection, as the old package did. `@opentelemetry/api-logs` must be a dependency of the app (`^0.223.0`).

### HTTP spans and metrics

The old package was frozen on `@opentelemetry/instrumentation-http` 0.218, which emitted the old HTTP semantic conventions. Upstream `instrumentation-http` emits only the stable keys since 0.221, and `OTEL_SEMCONV_STABILITY_OPT_IN` no longer brings the old ones back. Every saved search, dashboard and alert on HTTP keys needs an update:

| Old key                                                                                         | New key                                                 |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `http.method`                                                                                   | `http.request.method`                                   |
| `http.status_code`                                                                              | `http.response.status_code`                             |
| `http.target`                                                                                   | `url.path` and `url.query` (server spans)               |
| `http.url`                                                                                      | `url.full` (client spans; server spans have none)       |
| `http.scheme`                                                                                   | `url.scheme` (server spans)                             |
| `http.host`, `net.host.name`, `net.host.port`, `net.peer.name`                                  | `server.address`, `server.port`                         |
| `http.flavor`                                                                                   | `network.protocol.version`                              |
| `net.peer.ip`                                                                                   | `client.address` (server spans), `network.peer.address` |
| `net.peer.port`                                                                                 | `network.peer.port`                                     |
| `http.status_text`, `net.host.ip`, `net.transport`, `http.response_content_length_uncompressed` | none                                                    |
| metric `http.server.duration` (milliseconds)                                                    | `http.server.request.duration` (seconds)                |
| metric `http.client.duration` (milliseconds)                                                    | `http.client.request.duration` (seconds)                |

### Console logs

Console capture now uses the upstream `@opentelemetry/instrumentation-console`. The same calls inside an active span produce:

| Call                                          | Old record                                                             | New record                                                                     |
| --------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `console.log('plain string', 42)`             | body `plain string 42`, severity number 0                              | body `plain string 42`, severity number 9 (`info`)                             |
| `console.log({ userId: 7, action: 'login' })` | body `{"userId":7,"action":"login"}`, attributes `userId` and `action` | body `{ userId: 7, action: 'login' }` (the `util.inspect` form), no attributes |
| `console.info('info %s', 'fmt')`              | body `info %s fmt`                                                     | body `info fmt`                                                                |
| `console.warn('warn')`                        | severity number 0                                                      | severity number 13 (`warn`)                                                    |
| `console.error(new Error('boom'))`            | body `{}`                                                              | body `Error: boom` with the stack, severity number 17 (`error`)                |
| `console.debug('debug')`                      | severity number 0                                                      | severity number 5 (`debug`)                                                    |
| `console.trace('trace call')`                 | recorded as `error` with `Trace:` and a stack                          | one record, severity number 1 (`trace`), body `trace call`                     |
| `console.dir({ dir: 1 })`                     | not captured                                                           | body `{ dir: 1 }`, severity number 9                                           |

- The scope changed from `node-logger` to `@opentelemetry/instrumentation-console`, and the records carry the full resource, including `OTEL_RESOURCE_ATTRIBUTES` and the host and process attributes. Update saved searches on `ScopeName = 'node-logger'` or `SeverityNumber = 0`.
- Records carry the trace context, as before.
- Object arguments no longer become attributes. To keep searchable fields, log through pino or winston (their bundled instrumentations keep fields as attributes), or log `JSON.stringify(object)`, a JSON body the ClickStack collector parses into attributes.
- The old preload and the `opentelemetry-instrument` command captured no console output at all, because the old console instrumentation patched only modules that called `require('console')`. Apps started that way now send console records for the first time; expect new log volume.
- `OTEL_LOG_LEVEL=debug` no longer turns console capture off. The diagnostic output is not captured.

### Headers and bodies

- Header capture is an allowlist of exact names. The old package captured every header, without redaction, when advanced network capture was on. Headers on the sanitize list (`authorization`, `cookie`, `set-cookie`, `proxy-authorization`, `x-api-key` by default) are not captured at all, even when listed, and there is no `[REDACTED]` marker. Header keys (`http.request.header.<name>`, `http.response.header.<name>`) are unchanged.
- Bodies use the semantic-conventions keys `http.request.body.content` and `http.response.body.content`, plus `http.request.body.size` and `http.response.body.size`, instead of `http.request.body` and `http.response.body`.
- The old package replaced a whole body with `[Filtered]` when it contained a sensitive word anywhere. The new one redacts only the values of keys that contain `password`, `passwd`, `secret`, `token`, `api_key`, `apikey`, `api-key`, `authorization`, `cookie` or `session`: JSON keys in any captured textual body, including JSON sent as `text/plain` or form-urlencoded, and form-urlencoded fields. The list is fixed. One level of JSON escaped inside a string value, as in queue and webhook envelopes, is redacted too; deeper nesting and other nested encodings, such as URL-encoded JSON in a form field, are recorded as is. Redaction is a best effort: keep collector-side redaction as the backstop.
- Bodies are capped at 8192 bytes per body and direction, only textual UTF-8 bodies are recorded, and compressed bodies get a size only (the old package decompressed them synchronously). None of these rules can be changed. `fetch` bodies need Node.js 24.4 or later. `write()` and `end()` arguments such as an encoding or a callback are passed through unchanged; the old package dropped them.

### Trace attributes

`setTraceAttributes()` and `betaMode` have no replacement in this package. The upstream alternative is `BaggageSpanProcessor` (`@opentelemetry/baggage-span-processor`) and `BaggageLogRecordProcessor` (`@opentelemetry/baggage-log-record-processor`) with plain `NodeSDK` ([span processor](https://github.com/open-telemetry/opentelemetry-js-contrib/tree/main/packages/baggage-span-processor#readme), [log record processor](https://github.com/open-telemetry/opentelemetry-js-contrib/tree/main/packages/baggage-log-record-processor#readme)). It differs from the old feature:

- Baggage is propagated to downstream services in the `baggage` header, while the old attributes stayed in the process. Never put secrets in it.
- The entries reach spans that start after you set the baggage, and log records emitted in that context. Spans that are already open, such as the server span, do not get them.
- Baggage belongs to the request's context, so it does not leak into other requests, as the old shared context map could.
- Passing processors to `NodeSDK` stops it from building the trace and log exporters from `OTEL_TRACES_EXPORTER` and `OTEL_LOGS_EXPORTER`, so you pass those exporters yourself.
- Use the standard keys, which ClickStack is moving its UI to:

  | Old key              | New key                                                            |
  | -------------------- | ------------------------------------------------------------------ |
  | `userId`             | `user.id`                                                          |
  | `userEmail`          | `user.email`                                                       |
  | `userName`           | `user.name`                                                        |
  | `teamName`, `teamId` | a reverse-domain key of your own, for example `com.acme.team.name` |

### Telemetry volume and identity

- `telemetry.distro.name` is `clickstack-node` instead of `hyperdx`, and `telemetry.distro.version` is this package's version. Update saved searches that filter on them.
- Apps that used the old `init()` lost all instrumentation metrics and `fetch` spans, because `programmaticImports` re-patched modules in a way that skipped them. They now get runtime, HTTP and undici metrics and `fetch` spans: expect new metric and span volume.
- pino records are no longer sent twice. The old transport sent a second copy under the `node-logger` scope with severity number 0; only the bundled pino instrumentation's records remain. winston records are sent only once `@opentelemetry/winston-transport` is installed (see [Exports and import paths](#exports-and-import-paths)).
- The old Express error handler recorded only errors with status 500 or higher. The upstream Express instrumentation records every error thrown in a route or middleware, so 4xx errors raised as exceptions now count as errors.
- The router instrumentation is off by default. In Express 5 apps each middleware has one span, from `@opentelemetry/instrumentation-express`, and each route error one exception event; searches on the `@opentelemetry/instrumentation-router` scope find nothing. Express 4 apps are unaffected.
- No cloud resource detectors by default (see `OTEL_NODE_RESOURCE_DETECTORS` above).

### Sentry

The old Sentry integration is gone. `@sentry/node` runs next to this package with its own pipeline, so Sentry events do not carry the ClickStack trace ID.

- `@sentry/node` 11 registers no OpenTelemetry tracer provider unless `enableOpenTelemetrySetup: true` is set. Leave it unset; then the start order does not matter.
- `@sentry/node` 8 to 10 start their own OpenTelemetry setup. Start this package first and pass `skipOpenTelemetrySetup: true` to `Sentry.init()`. If Sentry starts first, or version 11 runs with `enableOpenTelemetrySetup: true`, `init()` logs a warning and does nothing.
- Crashes: Sentry leaves the exit to this package, which exports the FATAL record and exits with code 1. When Sentry's handler is present, the exit waits 2 seconds (Sentry's default `shutdownTimeout`) so that Sentry can send its crash event.
- Unhandled rejections: in Sentry's default `warn` mode the process keeps running and there is no FATAL record; console capture sends Sentry's warning as log records. In `strict` mode Sentry exits the process itself, and telemetry this package has not exported yet is lost.
- Errors thrown in instrumented route handlers are already recorded on spans. Where you call `Sentry.captureException(error)` yourself, also call `trace.getActiveSpan()?.recordException(error)` there. Sentry's `beforeSend` runs too late: the request span has usually ended.
- Each SDK sees the other's HTTP requests. Leave out Sentry's with the `ignoreOutgoingRequestHook` option of `@opentelemetry/instrumentation-http` in `instrumentations`, and the OTLP exports with `Sentry.httpIntegration({ ignoreOutgoingRequests })`.

## @hyperdx/node-logger

| `@hyperdx/node-logger`                            | Replacement                                                                                                                                |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `HyperDXWinston` transport                        | `@opentelemetry/winston-transport`, installed next to this package; the bundled winston instrumentation adds it automatically              |
| pino target `@hyperdx/node-logger/build/src/pino` | Delete it; the bundled pino instrumentation sends pino records                                                                             |
| `HyperDXNestLoggerModule`                         | A NestJS logger built on winston or pino; the bundled instrumentations send its records (winston needs `@opentelemetry/winston-transport`) |
| `HyperDXLogger.postMessage()`                     | The Logs API: `logs.getLogger('app').emit({ body, severityNumber })` from `@opentelemetry/api-logs`                                        |

Its variables are covered above: `HYPERDX_API_KEY` becomes `OTEL_EXPORTER_OTLP_HEADERS`, and `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME`, `OTEL_BLRP_*` and `OTEL_LOG_LEVEL` keep their meaning. `HYPERDX_API_URL` was never used.
